* **Update**: A build from source no longer fails on updater signing. `tauri build` wrote the platform installers and then exited 1 with `A public key has been found, but no private key`, which reads like the build broke when it had already succeeded. The cause is `bundle.createUpdaterArtifacts`: the Tauri CLI runs its signing step whenever that flag is on, and the private key is a release secret that no contributor's machine can hold. The flag moved out of `src-tauri/tauri.conf.json` into a new `src-tauri/tauri.release.conf.json`, which `release.yml` merges with `--config`, so signing runs only where the key exists. Reported as [#52](https://github.com/saschb2b/okf-studio/issues/52) against macOS, though the flag is platform-independent and Linux and Windows failed the same way. See [Build and Release](architecture/build-and-release.md). Verified on Ubuntu with `--bundles appimage`: exit 1 with the AppImage present before the change, exit 0 with the AppImage present after it, and exit 1 again when the release overlay is passed, which is the path CI takes. Not covered: no signed release ran end to end, so `latest.json` generation is unchanged but unproven here.

## 2026-07-28

* **Release**: 0.9.0. Speed reading. The reader's `Aa` control gains its second half, pace beside comfort: a focus player that shows one word at a time with the recognition point pinned so the word never moves, and a guided mode that sweeps a marker through the prose where it sits. A minor rather than a patch, on three counts: it is a new mode with its own keyboard map, it moves Move and Retire into an overflow so a familiar header no longer looks the way it did, and the whole design is a set of refusals a reader should be told about before meeting them (the player stops at a table or a code fence, no pacing mode is persisted, and the word-start cue ships off making no claim). Also in: agent turns stream in smoothly rather than arriving in blocks, and transcript text can be selected and copied.
* **Creation**: [Speed Reading](features/speed-reading.md) gives the reader's `Aa` control its second half — pace, beside comfort. A focus player shows one word at a time with each word's optimal recognition point pinned to a fixed position, and a guided mode paces a marker through the prose where it sits. Both read from one engine, so the two cannot drift on what "where am I" means.
* **Note**: The design is shaped by the objection to serial presentation rather than around it. Rayner et al. attribute the measured comprehension deficit of one-word-at-a-time reading to suppressed regressions: most backward eye movements exist to repair a misparsed sentence, and a forward-only player removes the repair along with the wasted travel. So rereading is inside the mode, not outside it — the current sentence stays printed beneath the frame, the arrows step by word and by sentence and each of those pauses the clock, and resuming rewinds three words. A player that could only go forward would have been the cheaper build and the version the evidence argues against.
* **Note**: The rate defaults to 300 wpm and names its own limit. Comprehension holds through roughly 400–600 wpm and falls away above that, so past 500 the player says so rather than letting the number climb quietly. The word-start emphasis cue ships **off** and claims nothing: a 2024 replication and a 2,000-reader field test both found no speed or comprehension effect for typical readers, with a more consistent signal among ADHD and dyslexic readers. Offering it as comfort is defensible; advertising it as speed is not.
* **Note**: The player refuses to tokenize a table, code fence, equation, or diagram — it stops and renders the block as itself. Sentence jumps stop there too, which was a real bug on the first pass: `nextSentence` moves token to token, so it sailed straight past a code block that the step-by-step path stopped at. Caught by an integration test walking the fixture by sentence looking for the stop.
* **Update**: No pacing mode is persisted, only the rate, frame size, and cue ([settings](ux/settings.md)). Text that advances on its own has to follow a press every time (WCAG 2.2.2), and a stored mode would arm a player for the next concept. The reader tags its pacing request with the concept it was made on, so navigating away ends the session by derivation rather than by an effect racing the render.
* **Update**: The guided marker is positioned from a range's geometry and changes no markup. The reader bakes its body HTML and re-applies it wholesale, so a highlight inserted into the text would be erased on the next render — the same constraint already documented for link cues and heading anchors, now with a second consumer.
* **Update**: `plainExcerpt`'s markdown stripping was factored into `plainBlocks`, which splits a body into blocks *before* stripping syntax. The excerpt is now derived from it, so there is one implementation of what counts as prose rather than two that could disagree about a table.
* **Fix**: The word moved. The frame and the sentence beneath it were stacked and centred as a pair, so a sentence one line longer than the last re-centred both and shifted the word — 9px, in both axes — which is precisely the thing a fixed fixation point exists to prevent. The frame is now anchored to the middle of the stage with the sentence hanging off that anchor and growing downward. Missed on the first review because every pivot measurement taken happened to fall inside one sentence; a story now walks sixty frames across several sentence boundaries and asserts the pivot's centre never changes. Reverting the layout makes it fail, which is the only reason to trust it.
* **Update**: The reader header is grouped, and Move and Retire moved into a **More concept actions** overflow. Five peer buttons in one row is past the point where a toolbar is scanned rather than read, and the established remedy is chunking plus progressive disclosure, not shrinking everything: reading controls (Speed read, `Aa`) sit together behind a hairline, Work with agent stays in view as the headline capability, and the two reviewed transactions go one click away at the right edge.
